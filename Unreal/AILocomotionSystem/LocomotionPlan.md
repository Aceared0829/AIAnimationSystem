# AIAnimationSystem 第一阶段开发方案：Locomotion

本方案属于 [AIAnimationSystem](../../README.md)，聚焦第一阶段的 Locomotion、跳跃与蹲伏。文中的 `AILocomotion*` 继续表示该阶段的插件与模块命名，不限制整个项目后续的角色动画范围。

日期：2026-09-07。状态：已确认的开发方向，尚未完整实现。

本方案以多人联机为默认需求，同时考虑 CMC 与 Mover。当前实现与验证范围以 [插件说明](README.md) 为准；本文中的规划能力不能作为现有功能声明。

## 先看整体

由 CMC / Mover 负责角色移动、碰撞、跳跃、蹲伏和网络预测；统一人形模型根据运动状态与未来轨迹生成姿态，再通过重定向适配不同角色。

第一阶段覆盖走跑、起停、转向、跳跃和蹲伏。翻越、攀爬和持枪暂不纳入。

训练入口是 Unreal 中的 `UAnimSequence` 资产。编辑器解析 `.uasset` 中的动画，完成采样和转换，Python 使用转换后的数据训练；Python 不直接解析任意 `.uasset` 文件。

目标是基础模型集中训练，更换角色主要做骨架适配，新增风格尽量少量微调。是否能够达到相同质量、需要多少数据与训练，必须通过实验确定。

```text
训练：
UE 动画资产 → 检查与采样 → 统一人形骨架 → 训练数据 → Python 训练 / 微调 → 模型包

运行：
玩家 / AI 输入 → CMC 或 Mover → 实际运动状态与轨迹条件
                                      ↓
                               统一人形动画模型
                                      ↓
                           角色重定向与接触修正 → 姿态
```

## 1. 范围与控制权

| 动作 | 移动后端负责 | 动画模型负责 |
| --- | --- | --- |
| 待机、走跑、起停、前后左右移动、转向 | 速度、加速度、制动、朝向与碰撞 | 步态、收步、转身和身体倾斜 |
| 跳跃 | 起跳许可、重力、空中控制和落地判定 | 起跳、腾空、下落与落地姿态 |
| 蹲伏 | 蹲伏许可、胶囊体尺寸、站起空间检查和速度 | 下蹲、蹲走与站起过渡 |

第一阶段以双足人形为通用范围，测试平地、坡面和移动后端支持的基础台阶。四足、额外肢体和极端比例另行评估。

常规移动通过后端正常模拟流程执行，不以每帧直接设置 Actor 位置代替网络移动。模型生成的根轨迹默认不直接改变角色位置。

保留受控动作位移接口，未来可通过 CMC RootMotionSource 或 Mover 对应机制执行特定动作。请求必须定义启动时间、持续时间、优先级、结束与取消规则。同一段运动只有明确的一套控制权，避免模型与移动组件重复施加位移。

Root Motion 本身可以用于联机。当前选择的理由是降低实时生成轨迹与网络预测、回滚之间的耦合，而不是认为 Root Motion 无法联网。

## 2. 三套骨架与统一表示

| 骨架 | 职责 |
| --- | --- |
| 来源骨架 | 动画资产原本使用的结构、命名和参考姿态 |
| 模型骨架 | 稳定、版本化的训练与推理表示 |
| 角色骨架 | 游戏最终显示的骨架，包括需要额外处理的辅助骨 |

训练前执行来源骨架到模型骨架的转换；运行时执行模型骨架到角色骨架的转换。不同角色优先复用同一模型，不按每个资产骨架重复训练。

以 Manny 人体结构作为初始参考，通过资产检查和姿态还原实验确定精简关节集。最终骨骼清单尚未确定，不直接把全部辅助骨、扭转骨作为模型输出。

骨架配置记录语义映射、父子关系、参考姿态、坐标轴、单位、肢体链、身体比例，以及缺失骨和辅助骨策略。明确区分 UE Root 的整体运动与 Pelvis 的身体运动。

“UE 骨骼”不代表结构一致。UE4 Mannequin、Manny 和自定义变体仍需检查。更换角色先做确定性的重定向配置，效果不足时再考虑学习式适配或微调。

Schema v2 导出器使用 Pelvis 子树，将每帧身体变换保存到 UE Root 局部空间，并把组件空间 Root 另存为只读审计轨道。训练清单声明 `pose_only_root_authoritative`，Root 模型不得消费该数据；旧 Schema v1 仍属于祖先运动合入骨盆轨迹的历史契约。

## 3. 数据制作闭环

### 3.1 资产盘点

以 UE 动画示例项目为主要起点，其他资产检查后逐批加入。统计骨架、时长、帧率、Root Motion、位移范围、动作类别和过渡覆盖。

先建立风格相对一致、覆盖完整的基准集，避免未经筛选混合所有资产。原地动画若没有可靠速度信息，不能凭空补成具有准确根轨迹的数据。

### 3.2 采样、重定向与清洗

通过 Unreal 解析动画，统一骨架、参考姿态、坐标、单位和采样率。检查脚穿地、肢体伸长、朝向错误、Root 与 Pelvis 混淆、非根平移和缩放等问题。

尽量保留可追溯的原始采样及资产来源，统一骨架转换作为明确步骤记录。当前数据集要求结构一致；自动跨骨架统一尚未实现。

### 3.3 训练字段

保存姿态、运动轨迹、速度、朝向、足部接触和站立 / 蹲伏 / 腾空状态。阶段与接触标签可自动估计，但需要可视化检查与修正方式。

按完整动画片段或来源划分训练、验证与测试数据，避免相邻帧或重复动作跨集合泄漏。骨架定义、特征布局、统计量、采样率和标签约定均需版本化。

### 3.4 先还原，再训练

将转换数据重新显示到 UE，逐项对照源动画。先确认数据能正确往返还原，再用训练结果评价模型。合成夹具测试不能替代真实资产验证。

## 4. 模型与少训练路线

复用 MotionBricks 的架构、动作编码和条件生成思路，建立独立于 G1 的人形数据与推理路径。G1 权重仅作为迁移实验候选，不作为最终系统的唯一基础。

并行意义上的实验对照如下，不要求同时实施：

| 实验 | 目的 |
| --- | --- |
| 统一人形基线 | 用小规模人形模型验证数据、训练任务与运行时闭环 |
| 预训练迁移 | 尝试输入输出适配、冻结部分网络和局部微调，比较同等数据预算下的质量与成本 |

骨架维度变化、归一化统计和 VQ 码本语义均会影响迁移。适配器、冻结策略和教师监督只有在实验有效后才纳入默认流程。当前自定义 UE 训练入口从头训练，不支持直接加载 G1 权重进行该迁移。

少训练主要依靠统一表示、多角色复用、风格条件以及有依据的局部微调。传统动画播放或 Motion Matching 可作为对照基线，用于衡量模型新增的价值。

不能简单删除现有 Root 输出并把姿态贴到胶囊体上。需要调整条件输入、训练目标和姿态还原，使身体动作与外部受约束轨迹匹配；具体网络改动在基线实验后确定。

## 5. 运行时数据与推理时序

| 公共输入 | 用途 |
| --- | --- |
| 实际位置、速度、朝向与角速度 | 对齐已经发生的移动 |
| 期望方向、速度与朝向 | 提前准备起步、转向和停止 |
| 地面、腾空与蹲伏状态 | 控制动作阶段 |
| 重力方向、地面法线、移动基座信息 | 处理环境与参考空间 |
| 带时间的未来轨迹估计 | 提供预测条件，不保证碰撞后的实际轨迹相同 |
| 时间戳与纠正版本 | 识别过期推理和失效历史 |

输出以模型空间姿态为主，可包含接触与动作阶段；可选根轨迹建议默认不直接应用。目标角色输出需恢复骨轴约定，并结合接触修正。IK 或轨迹调整不能保证消除所有滑步。

异步推理结果绑定输入时间与状态版本。撞墙、提前落地、传送和网络纠正时丢弃过期结果，必要时重建历史并平滑切换。区分移动模拟时间与动画呈现时间，避免把插值后的显示状态错误地用于重演。

推理超时、模型加载失败或结果无效时使用传统动画回退，角色移动仍正常运行。模型格式、推理后端、频率和缓存长度经过目标硬件测试后确定。

## 6. CMC 与 Mover 接入

公共层不依赖具体移动后端，也不强制所有使用者继承 ACharacter。每个角色选择一个后端；两者共享模型契约，但不要求产生逐帧一致的运动轨迹。

| 适配层 | 职责 |
| --- | --- |
| CMC | 获取移动状态、估计轨迹、接入移动模式和纠正；新增影响移动的输入参与 SavedMove 保存、传输与重演 |
| Mover | 接入输入、模拟状态、移动模式及回滚通知；核对所选网络后端、模拟步长和线程约束 |

可以先通过 CMC 跑通完整链路，但移动接入阶段也必须完成 Mover 验证，不能仅用空接口宣称支持。

本机 UE 5.8.2 源码中的 Mover 仍标记实验性，RootMotionAttribute 路径注明仅支持 Independent ticking。该限制只针对具体路径，不等同于所有 Mover Root Motion 路径的限制。实现时重新核对引擎版本及选用路径。

## 7. 多人联机

服务器决定权威移动、碰撞、动作许可和关键游戏状态。本地玩家客户端进行移动预测与动画推理，其他客户端依据同步后的运动状态生成远端表现。

默认不逐骨骼复制，也不要求专用服务器为纯视觉表现运行完整模型。按需要同步动作事件、阶段和风格参数；不保证每个客户端生成完全相同的视觉姿态。若姿态参与命中判定，另行设计权威姿态或可验证碰撞表示。

推理尽量位于移动回滚关键路径之外。随机种子不能单独保证不同设备和不同推理时机下的轨迹一致。未来若模型参与实际位移，必须补齐服务器验证、轨迹记录或同步、回滚重放和推理未完成时的行为。

## 8. 插件与工具组织

外层 AILocomotionSystem 为插件集合目录，按独立依赖和启用需求划分：

| 插件 | 规划职责 | 当前状态 |
| --- | --- | --- |
| AILocomotionCore | 公共契约、骨架配置、模型元数据与版本 | 待实现 |
| AILocomotionDataset | 编辑器采样、检查与数据导出 | 实验性实现，需扩展 |
| AILocomotionRuntime | 推理、姿态输出、重定向接入与回退 | 待实现 |
| AILocomotionCMC | CMC 适配 | 待实现 |
| AILocomotionMover | Mover 适配 | 待实现 |

Python 预处理、训练和评估与插件配套维护。模型包需绑定骨架版本、特征定义、归一化统计、码本及模型依赖、输入输出约定；不兼容的组合明确拒绝加载。早期不为每个小功能单独拆插件。

## 9. 实施顺序与验收

| 阶段 | 交付物 | 通过标准 |
| --- | --- | --- |
| 1. 数据闭环 | 真实 UE 动画导出、统一骨架配置与还原预览 | 真实资产采样、转换及还原正确 |
| 2. 移动接入 | CMC / Mover 适配、传统动画回退 | 无模型时也可完成联机移动和状态切换 |
| 3. 模型闭环 | 人形小模型、UE 推理与姿态输出 | 可交互完成基础动作，推理失败可回退 |
| 4. 泛化验证 | 多骨架、多比例角色与迁移对照 | 明确无需训练、需要适配和需要微调的范围 |
| 5. 联机与性能 | 延迟、丢包、纠正及多人压力测试 | 移动正确性保持，动画恢复和性能符合预算 |

持续评估操控响应、滑步、穿地、关节异常、过渡质量、推理耗时、资源占用和纠正后恢复。分别记录 CMC 与 Mover 结果；涵盖急停急转、碰墙、跳跃落地、低顶站起失败、坡面及移动基座。

目标平台、硬件、同屏人数、推理预算和网络测试参数尚待确定，验收阈值在性能阶段前明确。不得以训练损失下降代替动作质量或联机验证。

## 10. 当前证据与下一步

已有实验性编辑器导出器、自定义 UE 骨架数据转换和训练入口。此前通过 UE 5.8.2 UHT、模块编译及 DLL 链接，以及合成动画上的 CPU 小网络测试；这些是既有验证记录，本次方案提交不代表重新执行。

真实资产菜单导出、完整训练质量、GPU 训练、标准分发包，以及运行时与 CMC/Mover 接入仍未验证或未实现。详情见 [当前插件状态与使用说明](README.md)。

下一步先选取真实 UE 动画，完成“采样 → 统一骨架 → 还原预览”，再推进移动接入和模型实验。
