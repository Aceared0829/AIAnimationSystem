# 记录研究实验

本项目把简明、可核对的实验记录提交到 `docs/experiments/`。训练检查点、原始数据及大体积运行输出保留在既有本地目录；记录应让读者找到其来源，并理解哪些结论已经实测。先读 [实验索引](../../../docs/experiments/README.md)，新记录从 [模板](../../../docs/experiments/_template.md) 复制。已有专题报告不必搬迁；新记录可链接它们。

## 何时记录

- 对数据采集、重定向、清洗、划分和人工验收，模型训练或消融，离线评估，推理性能，以及 UE 内效果验证，建立一项有明确问题和可观察结果的实验记录。失败、中止、负结果同样记录。普通代码修改或尚未执行的设想不冒充实验。
- 开始实验时可建立状态为“进行中”的记录，结束后补齐实际命令、最终状态和证据。用户只要求整理日志时，不据此启动训练、数据处理或 UE 验证。
- 每个可独立引用的实验使用 `docs/experiments/YYYY-MM-DD-short-slug.md`；同日重名时加短后缀。更新索引，说明记录状态。对同一实验的续跑、修正和复核，保留日期与修订说明，不覆盖原始失败或旧结果。

## 记录可复核的事实

1. 写清研究问题、改动、对照组、执行日期、执行者或来源、状态及停止条件。区分上游 MotionBricks 成果、本项目新增实现和外部数据；不能把引用的结果写成本项目实测。
2. 记录代码提交 SHA；若实验使用未提交修改，写明 `dirty`、相关文件或补丁位置，不能只给 SHA。保存实际命令和**生效**配置、随机种子、依赖版本、设备。训练要补充初始化/续训检查点、步数或 epoch、批量、学习率与重要损失/采样设置；不适用项说明原因。
3. 记录数据来源及版本、清单/契约/骨架/统计量或样本哈希、训练/验证/测试划分及数量、排重与泄漏检查、人工审核范围。当前 `pose_only_root_authoritative` 的 Root/姿态职责与条件可见性以实际数据契约为准；不要混淆理想未来 Root、真实控制输入和目标标签。
4. 对每个结果给出指标定义、单位、聚合方法、评估划分和样本数，并附原始报告、图、检查点或审核回执的位置及可用的哈希。对照实验写明固定变量和不同变量；不要把训练时长、数据版本或测试口径不同的结果当成同条件提升。把直接测量、工程推断、未验证项分开写。
5. 如实记录异常、失败、人工视觉结论与限制。离线骨架/数值结果不代表 UE 蒙皮、IK、碰撞、连续游戏控制或多人运行时效果。论文候选表述只能覆盖证据支持的范围。

## 提交边界

记录正文与索引属于 Git 提交内容；实验完成或日志更新时，选择性暂存并提交它们及本次相关的小型配置/图表。先检查 `git status` 和暂存差异，保留工作区其他人的改动。`training/runs/`、`data/raw/`、`data/prepared/`、权重与大体积输出按现有忽略规则留在本地；不要为了提交日志而强制加入这些文件。日志中保留稳定的 run ID、可访问位置及哈希，区分仓库可复现命令与仅本机有效的绝对路径。提交前排除密钥、私人数据和无授权再分发的原始素材。
